# Lead Automation API

A lead intake and automation API built with **Python, FastAPI, PostgreSQL, SQLAlchemy, and n8n-compatible HTTP endpoints**. It validates lead data, calculates explainable scores, records activities and score history, and provides reports.

## Features

- Receive leads through REST API endpoints
- Validate required fields, email addresses, and Iranian mobile numbers
- Detect duplicate phone numbers and email addresses
- Score qualified leads using ICP fit, budget, timeline, and recent activity signals
- Categorize scored leads as **Hot**, **Warm**, or **Cold**; incomplete profiles can remain unclassified
- Store lead records in PostgreSQL using SQLAlchemy
- Generate statistical reports with lead counts and percentages
- Expose HTTP endpoints for separately configured n8n workflows
- Support Telegram notification workflows when n8n and Telegram credentials are configured

## API Endpoints

### 1. POST `/webhook`

Receives and validates standard lead information.

Example request:

```json
{
  "name": "Ali Ahmadi",
  "job": "Web Developer",
  "city": "Tehran",
  "phone": "09123456789",
  "email": "ali@example.com"
}
```

### 2. POST `/qualified-lead`

Receives lead information with additional qualification fields and calculates a score and category.

Example request:

```json
{
  "name": "Test Customer",
  "job": "Automation Test",
  "city": "Test City",
  "phone": "09120000000",
  "email": "test-qualified@example.com",
  "budget": "yes",
  "timeline": "this_month",
  "need": "clear"
}
```

The scoring system combines configured ICP fit with budget, timeline, and recent activity signals. Rules and weights are defined in `configs/scoring.json`. The score is a transparent heuristic, not a purchase-probability estimate.

### 3. POST `/leads/{lead_id}/activities`

Records a lead activity using `X-Activity-API-Key`. Supported types: `demo_booked`, `quote_requested`, `contact_form_submitted`, `sales_email_reply`, and `pricing_page_view`. The timestamp is generated by the server in UTC. Activity insertion, lead rescoring, and score-history insertion run in one transaction; if scoring fails, the transaction is rolled back.

### 4. GET `/report`

Returns statistical information about stored leads, including:
- Total leads
- Hot, Warm, and Cold leads
- Unclassified leads
- Lead category percentages

## Installation

Clone the repository:

```bash
git clone https://github.com/garachoban80-code/lead-automation-api.git
cd lead-automation-api
```

Create and activate a virtual environment:

```bash
python -m venv .venv
source .venv/bin/activate
```

Install dependencies:

```bash
pip install -r requirements.txt
```

## Environment configuration

Create your local environment file:

```bash
cp .env.example .env
```

Edit `.env` locally and configure `DATABASE_URL`, `API_KEY`, and `ACTIVITY_API_KEY`. Use strong, separate secrets of at least 32 characters for the two API keys. The PostgreSQL database and role referenced by `DATABASE_URL` must already exist and be accessible.

Never commit `.env` or publish API keys, database passwords, or real customer data.

## Database migrations

After configuring `.env` and creating the PostgreSQL database and role, apply the schema migrations:

```bash
alembic upgrade head
```

The API and repository integration tests use a separate database named `lead_automation_test`. Apply migrations to that test database before running the test suite. The tests truncate its lead, activity, and score-history tables; never run them against a production or data-bearing database.

## Run the API

```bash
uvicorn lead_api:app --host 127.0.0.1 --port 8000 --reload
```

API base URL:

`http://127.0.0.1:8000`

Interactive API documentation:

`http://127.0.0.1:8000/docs`

## Scoring and score history

The ICP and scoring rules are configured in `configs/scoring.json`. The transparent heuristic currently combines Fit (40%) and Intent (60%). It is not a trained machine-learning model and does not predict purchase probability.

`lead_score_history` stores snapshots for `migration_baseline`, `lead_created`, and `activity_recorded`. The migration preserves existing scores without recalculating them.

## Run tests

Activate `.venv` and run:

```bash
python -m unittest discover -s tests -v
```

The API and repository integration tests use the separate PostgreSQL database `lead_automation_test`. Tests truncate its lead, activity, and score-history tables. Apply migrations to the test database before running tests, and never point the test suite at a production database.

## n8n Integration

The API can be connected to n8n using Webhook and HTTP Request nodes. Workflows can forward incoming lead information to FastAPI, process the response, route leads based on category, and send notifications through Telegram.

A separate report workflow can request `/report` and deliver the statistics to Telegram.

## Data and Security

Lead records are stored in PostgreSQL. Legacy JSON files may contain customer data; keep them out of public repositories.

Do not publish API keys, bot tokens, passwords, or real customer information.
